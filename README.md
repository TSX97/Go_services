INK3 — Микросервисный мессенджер

INK3 — это масштабируемая микросервисная архитектура мессенджера, разработанная для высокой производительности, безопасной связи и быстрой доставки сообщений.

На данный момент структура репозитория и инфраструктура полностью инициализированы, а первый микросервис (Account Service) запущен и работает.

🛠 Технологический стек

Архитектура построена с использованием современных инструментов с упором на контейнеризацию, чёткое разделение ответственности и автоматизацию локальной разработки:

· Язык бэкенда: Go (Golang) v1.26 с использованием Go Workspaces (go.work) для чистого управления зависимостями между модулями.
· База данных: PostgreSQL v16 (контейнер на базе Alpine).
· Драйвер: pgx/v5 с пулом соединений через pgxpool.
· Контейнеризация: Docker и Docker Compose для полной изоляции окружения.
· Локальная автоматизация: Makefile и кастомные shell-based Git-хуки.

🧬 Структура проекта

Проект использует монорепозиторий на основе Go Workspaces, что позволяет нескольким изолированным сервисам сосуществовать в одном репозитории:

```text
.
├── .TODO                 # Дорожная карта проекта и предстоящие задачи
├── .env                  # Локальные переменные окружения (игнорируются git)
├── .env.example          # Шаблон для переменных окружения
├── .git-config           # Общие командные настройки Git
│   ├── aliases           # Кастомные сокращения для разработки (st, df, lg и т.д.)
│   └── hooks             # Автоматические проверки качества
│       ├── commit-msg    # Проверяет стиль именования коммитов
│       └── pre-commit    # Проверяет форматирование и синтаксис кода
├── .gitignore            # Правила исключений Git
├── Makefile              # Точка входа для автоматизации локальной настройки
├── README.md             # Документация проекта
├── cmd                   # Исходный код микросервисов
│   └── account           # Модуль Account Service
│       ├── .dockerignore # Правила исключений для сборки Docker
│       ├── Dockerfile    # Многоэтапная сборка на scratch-образе
│       ├── go.mod
│       ├── go.sum
│       └── main.go       # Точка входа приложения
├── db                    # Общий модуль базы данных
│   ├── connection.go     # Конфигурация пула соединений
│   ├── go.mod
│   ├── go.sum
│   └── ping.go           # Проверка доступности базы данных
├── docker-compose.yml    # Оркестрация инфраструктуры
└── go.work               # Конфигурация Go workspace, связывающая модули
```

⚓ Git-хуки и автоматизация

Для обеспечения качества кода и чистой истории VCS в команде в репозитории используются автоматические хуки, расположенные в .git-config/hooks/. Запуск инициализатора workspace мгновенно подключает их.

pre-commit:

· Проверяет подготовленные к коммиту файлы перед разрешением коммита.
· Проверяет форматирование Go-кода через gofmt.
· Динамически извлекает модули из go.work и запускает go vet для выявления синтаксических ошибок или ошибок статического анализа до отправки на сервер.

commit-msg:

· Обеспечивает соблюдение формата conventional commit с использованием строгих правил regex.
· Разрешённые префиксы: fix, docs, dev, bugfix, refactor, infra (например, bugfix(account): set correct connection to database).

🚀 Быстрый старт и локальная настройка

1. Инициализация окружения

Перед написанием кода или внесением изменений настройте локальное окружение (устанавливает Git-хуки, применяет кастомные Git-алиасы и выводит текущий список задач из .TODO):

```bash
make init
```

2. Настройка переменных окружения

Создайте локальный файл .env в корневой директории на основе шаблона .env.example:

```bash
cp .env.example .env
```

Убедитесь, что DB_HOST явно установлен в значение database (имя сервиса в Docker Compose), чтобы Go-приложение могло обнаружить контейнер с базой данных внутри изолированной сети.

3. Запуск архитектуры

Запустите контейнер с базой данных (с включёнными проверками работоспособности) и автоматически инициируйте многоэтапную сборку Docker для Account Service:

```bash
docker compose up --build
```

Контейнер Account Service безопасно блокирует своё выполнение и ждёт, пока база данных PostgreSQL не станет полностью работоспособной и готовой принимать соединения, после чего запускает HTTP-сервер на порту :8080. выпо
